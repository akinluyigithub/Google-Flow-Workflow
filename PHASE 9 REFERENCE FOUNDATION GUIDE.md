# Phase 9 reference foundation

Create the reusable reference library before final character assets, Flow Character setup, or storyboard generation. This is a dependency order, not a suggestion to batch every prompt at once. A single attractive portrait is not a complete character reference sheet.

## Required production order

1. **Character reference sheets for the full cast.** Make large **16:9 landscape** sheets for every involved character. Show the same identity in a full-body front view, full-body back view, left and right side/profile views, three-quarter view, and a clear head/face close-up. Make additional separate 16:9 pages when the panels would become too small to inspect. Cover physique, proportions, height/scale, face/head structure, hair, wardrobe front/back, footwear, and distinctive details. Keep neutral poses, lighting and backgrounds sufficient to compare identity. Name pages/views clearly and preserve the character's stable reference identifier. Check the face, build, hair, outfit, colors and proportions across every view; fix inconsistencies before proceeding. Do not invent a new face for each angle.
2. **Location reference sheets.** Create large 16:9 sheets or separate pages for every recurring location. Include an establishing view, reverse/side angles, entrances/exits, character positions and scale, key objects, lighting/time/weather, and a simple spatial layout where useful. For vehicles, establish driver side, wheel/dashboard, doors, cab partition, passenger aisle and sightlines explicitly. Keep clean empty plates separately when they will serve as generation ingredients. A contact sheet is for reference, not a substitute for a full-size clean location input.
3. **Prop reference sheets.** Create the necessary story props before scene images. Show overall form and scale, front/back/side views where relevant, material/color, orientation, operational parts and how the object is held or placed. Include wearable continuity items when important. Use large 16:9 pages or additional readable pages. Keep exact text for editing when generation cannot render it reliably. Check physical logic and compatibility with the character/location library.
4. **Final standalone character assets and saved Flow Characters.** Use the verified character sheets and relevant location/prop references as actual prompt inputs to derive consistent **9:16 portrait** character images. Preserve any already approved identity; repair missing views around it rather than redesigning it. Then add the selected character image(s) from the project to Flow's sidebar Characters, save the name and character information, create and explicitly attach the named saved voice for each speaker, and verify the sheet as required in the Character and Voice Guide. Do not force an entire multi-panel sheet into a single video frame; use the clearest single-view identity asset(s) supported by the Character UI.
5. **Scene and shot images.** Only after the foundation and Character/voice setup pass QC, produce individual **9:16 portrait** scene/shot images using the appropriate saved Characters, character sheets, location plates and prop references as real inputs. Check identity, wardrobe (including exact scarf color/shape), anatomy, scale, geography, prop ownership, lighting and neighboring-shot continuity. Keep shot images separate from reference sheets and label them in story order.
6. **Video preparation.** Confirm the foundation ledger is complete and the images are selected/locked. Use Omni 1.1 Flash with the actual relevant saved Character/voice inputs in its supported mode. Per-clip prompt/settings/live-cost approval remains required.

## Batch plan, labels, and completion

Include the multi-view pages, locations, props, final portraits and shot images in the production asset plan before the image-provider choice. Batch independent generations within a stage when practical, but wait for upstream references to be inspected and supplied before generating dependent assets. Do not replace the ordered stages with unrelated text-only generations. Missing foundation references are production work to correct; do not mark them complete because shots already exist.

Use a stable reference number with readable page/view suffixes, for example `REF 01A — Daniel turnaround`, `REF 01B — Daniel face and details`, `REF 03A — Bus geography`, and `REF 04A — Passenger list prop views`. Keep final portraits and `SHOT 01` assets distinguishable. Track actual Flow asset identities, views covered, requested/actual aspect, reference dependencies, QC and user approval state. Use separate full-size inputs where a multi-panel sheet would confuse generation. Follow the Asset Naming and Review Guide.

All Flow-generated references remain in Flow for review and reuse; no image download is required to complete this stage. Save ChatGPT-generated files in the local project folder when accessible and upload them to Flow. Existing approved assets remain valid unless a specific correction affects them. Repair the missing foundation, audit downstream dependencies, and identify only the images or clips that need renewed review.
