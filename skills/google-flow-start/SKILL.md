# Google Flow Start

Use this skill to activate the user's established Google Flow workflow, especially when a fresh chat has no prior conversation context.

## Startup and resume

1. Treat `FlowStart` or `Flow Start` as a direct command to start, even when it is the entire message. **Do not send any user-facing text, ask a question, do research, read workspace files, or show a menu before the first in-app browser tool call.** Do not ask what the trigger means, give a generic greeting, or stop after acknowledging it.
2. **First tool action: control the ChatGPT/Codex built-in in-app browser.** If using the CUA browser tool in a fresh tool session, its required first API call is `await cua.getState()`; read its returned documentation/state, then use its in-app browser controls. Navigate to `https://flow.google.com/` even if the current tab shows an older project. If signed out, stop at the sign-in page for the user to sign in within this in-app browser; do not switch browsers. Once the Flow main page is visible and signed in, click **+ New project**, wait for navigation, and verify a new project workspace is open. Only after these steps may you send a user-facing question, menu, or status message. Do not open, resume, or create within an older project for a fresh `FlowStart` run. Never launch, foreground, or switch to the user's external browser, and never use one as a fallback.
3. **Keep the in-app Flow browser session open for the entire project.** Keep the active project visible in the same in-app tab across turns, phases, user-input pauses, and status updates. Never invoke a close-tab/close-window action, hide/replace the browser, or navigate away from the active project until the workflow is complete or the user asks. Preserve and reuse the active tab/session identifier when the browser tool exposes one. If the tab/session is unexpectedly lost, reopen Flow in the in-app browser and return to the active project; never switch to an external browser. Before ending a turn mid-project, leave the in-app browser showing the active Flow project.
4. Only after the new Flow project is open, locate and read `system prompt.md` and `UNIVERSAL VIRAL VIDEO WORKFLOW.md` in the active Google-Flow workspace. The usual workspace is `C:\Users\ak\OneDrive\Documents\1 - Google-Flow`. If the active workspace differs, search the user's current project/workspace for those canonical filenames. The repository copies are the source of truth.
5. Start a fresh project state for this new project and begin at decision Gate 1, carrying forward only relevant brief details already present in this conversation. Do not resume state from an older Flow project. Resume an existing project only when the user explicitly asks to continue or resume it.
6. After each user choice, immediately show the next relevant options and continue the workflow. Keep to the canonical five-decision target and seven-decision maximum before images; bundle decisions and infer routine details. Keep choices short, numbered or lettered, and include a recommendation, “Choose for me,” and “Describe my own” when applicable.
7. If in-app browser controls are unavailable, do not substitute a question or external browser. State that the required first action could not be completed, and continue with non-browser work only if useful. If repository files are temporarily unavailable, proceed using the essential rules below and tell the user only if the missing files prevent a specific action. Never silently treat `FlowStart` as an ordinary text message.

## Essential workflow rules

- Research current, dated signals before trend, genre, hook, or platform recommendations. Cover TikTok, YouTube Shorts, and Instagram Reels, plus platforms requested by the user. Cite sources, distinguish evidence from creative inference, and never promise virality. Always include **viral micro-drama series** as a format option.
- If the user selects viral micro-drama, ask the regional/drama-type menu first (South Korean, Japanese, Chinese, English-language, American, British, Nigerian, Other/suggest your own, or Choose for me). Do not research or pitch stories before this selection unless already answered. English is always the default for dialogue, narration, captions, and voice language across regional options because the audience understands English; change language only when the user explicitly requests it. Region sets story context/setting, not spoken language, and does not imply an accent. After the choice, research current platform signals for the English-speaking audience and credible cultural/industry sources before presenting story options; then recommend a researched story and offer quick approve/revise/another-story choices without another setup interview.
- Bundle the creative brief, audience/platform, researched direction, story, cast and voice design, locations/props, script, shot structure, aspect ratio, audio, continuity, and image plan. The user wants concise, easy selections and a complete recommended proposal rather than many appearance questions. Make options specific and vivid using the supplied 243-entry `STYLE LIBRARY.md`, the creative brief, and current research; don't default to generic industry categories.
- Make the first creative-direction menu a rich, practical menu of at least 10 choices when the catalog supports it. Always show **Browse all 243 styles by category** and **Search all 243 styles** as explicit options alongside the recommendation, genre/story formats (including viral micro-drama), featured styles, choose-for-me, and custom-style routes. For approval gates, keep the compact approve/revise/stop menu.
- Follow all twelve phases in `UNIVERSAL VIRAL VIDEO WORKFLOW.md`, including the professionally formatted Google Docs posting package in Phase 12. Maintain project continuity and the user's chosen workspace/project folder.
- Still images: ask once whether to use ChatGPT Images or Google Flow Images. That provider choice authorizes the approved planned still batch. Generate the planned images together when practical, inspect each for prompt match, continuity, physical plausibility, and visual defects, autonomously retry clear failures within scope, then present the set for selection.
- Video: Google Flow is the renderer. Before every individual video clip, present that clip's exact prompt, model, mode, ratio, duration, output count, and live displayed cost. Generate only after explicit approval of that exact clip. One clip per approval by default. Never infer video approval from `FlowStart` or image approval.
- Asset naming is mandatory before review: immediately rename each completed/imported asset in Flow and verify the saved title. Use `REF 01 — Description` for references, `SHOT 01 — Story beat` for storyboard images, `CLIP 01 — Story beat — v01` for videos, and `SCREENSHOT 01 — Purpose` for UI captures. Number shots in story order, preserve identifiers through revisions, and distinguish coexisting versions. Keep identifier/title/asset URL or ID/version/review status/verified local path in the project asset ledger; reuse the identifiers in prompts, downloads, feedback, and edit maps. Present a labeled review list and never ask for batch selection while review tiles still have unexplained automatic titles. Follow the workspace's `ASSET NAMING AND REVIEW GUIDE.md`; cleanup follows user authorization and exact asset identification.
- Editing and publishing: follow the approved phase sequence and relevant available editing skill/plugin. Do not publish or post without explicit authorization.
- Resolution preference: use the highest supported download/upscale resolution with no added money or credit cost and no plan upgrade. Free 2K image upscaling is the standard when available, rather than 1K-only delivery. Verify live availability/cost evidence, downloaded pixel dimensions and visual fidelity; preserve useful originals and record native/upscaled status and actual paths in the asset ledger. The user's standing preference authorizes free upscaling without another question. If a higher tier is paid or its cost is unclear, use the best confirmed free version and disclose the limit; retain paid video approval requirements.
- Be honest about browser control, saved files, generated media, and current UI/model/cost uncertainty. Verify live settings in Flow before any generation; documentation and tutorials can become outdated.
- On every fresh `FlowStart`, open `https://flow.google.com/` in the ChatGPT/Codex built-in in-app browser and click **+ New project** as the first action, before research, planning, questions, or menus. Do not reuse the project currently open or resume old project state unless the user explicitly asks to resume. For any other browser-based task or test, default to the in-app browser. Never open or switch to the user's external browser.
- Keep the in-app browser tab visibly on the active Flow project through the whole project; never close, hide, replace, or navigate it away mid-work. Leave it open at the end of every in-progress turn. Close only after project completion or explicit user request.
